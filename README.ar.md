# كرفان

[![CodSpeed](https://img.shields.io/endpoint?url=https://codspeed.io/badge.json)](https://app.codspeed.io/Ercaner1988/kervan?utm_source=badge)

بنية بوابة توجه استخدام الذكاء الاصطناعي من واجهات الويب إلى نقاط النهاية المطلوبة. Rust، ملف ثنائي واحد.

> حملتُ على دروب كثيرة، وأعلمُ ما يتحمّلُ كلُّ طريق.

---

## 📦 المتطلبات

| المتطلب | الإصدار / ملاحظة |
|---|---|
| Rust | 1.88+ — المشروع يستخدم `edition = "2024"` و let-chains؛ سلاسل الأدوات الأقدم لا تستطيع البناء |
| Firefox | Zen أو Firefox القياسي |
| geckodriver | يبحث عنه الخادم عند التشغيل: `KERVAN_GECKODRIVER` أو `%LOCALAPPDATA%\kervan\bin\geckodriver.exe` (بما في ذلك استخدام جسر الإضافة وحده) |
| نظام التشغيل | Windows، Linux، macOS |

## 🛠 الوظائف والميزات

يحوّل حسابات الذكاء الاصطناعي بدون مفاتيح API (واجهات Gemini و Claude و Perplexity) إلى نقطة نهاية واحدة متوافقة مع OpenAI. بدلاً من نسخ ملفات تعريف الارتباط، يشغّل **متصفحاً حقيقياً**: تسجيل الدخول مرة واحدة، والجلسة تبقى في دليل الملف الشخصي.

الفرق عن الحلول الموجودة في ثلاث نقاط:

- **عزل حقيقي لكل حساب** — كل حساب في ملفه الشخصي الخاص. وضع التصفح الخاص لا يكفي: كل نوافذ التصفح الخاص في نفس المتصفح تتشارك ملفاً شخصياً واحداً.
- **جلسة دائمة** — لا لصق لملفات تعريف الارتباط، لا تجديد عند دورانها.
- **بوابة بشرية** — لا يفشل بصمت عند جدار التحقق؛ يوقف الحساب، يجلب النافذة إلى المقدمة، ويتركك تحلّه. لا يحاول تجاوز كشف الروبوتات.

## ⚙ التثبيت

### خطوات التثبيت

1. استنسخ المستودع:

```bash
git clone https://github.com/Ercaner1988/kervan.git
cd kervan
```

2. ابنِ المشروع:

```bash
cargo build --release
```

3. أنشئ ملف التكوين:

```bash
cp kervan.toml.example kervan.toml
```

4. عرّف حساباتك في `kervan.toml`.

### الاستخدام

```bash
./target/release/kervan --serve
```

يعمل الخادم على `127.0.0.1:20129`. نقطة نهاية متوافقة مع OpenAI:

```bash
curl http://127.0.0.1:20129/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model": "gemini", "messages": [{"role": "user", "content": "مرحباً"}]}'
```

أوضاع التشغيل:

| الوضع | ما يفعله |
|---|---|
| `--serve` | يشغّل الخادم (نقطة النهاية + جسر الإضافة). `--port <n>` يغيّر المنفذ. |
| `--giris <حساب>` | يفتح نافذة متصفح الحساب لتسجيل دخول يدوي مرة واحدة. |
| `--tara` | يعيد فحص حالة الجلسة للحسابات المعرّفة. |
| (بلا مُعلِّم) | وضع جلسة واحدة: يفتح الملف الشخصي وينتظر Enter — لا يشغّل الخادم. |

تعريفات الحسابات وكل الحقول: `kervan.toml.example`.

### جسر الإضافة (WebSocket)

إضافة المتصفح موجودة في `eklenti/` وتتصل بكرڤان دون WebDriver:
`ws://127.0.0.1:20129/ws/eklenti` (الخادم لا يزال يبحث عن geckodriver عند بدء
التشغيل — انظر المتطلبات). تسجّل الإضافة جلسة كل تبويب بمفتاح `provider:profile`؛
الملف الشخصي هو `cookieStoreId` في Firefox، أو `varsayilan` إن غاب.

**التثبيت الأول (مرة واحدة):**

1. Firefox ← `about:debugging#/runtime/this-firefox` ← **Load Temporary Add-on…**
   ← اختر `kervan/eklenti/manifest.json`.
2. يجب أن يكون كرڤان مشغّلاً بـ `--serve`؛ أثناء توقف الخادم تعيد الإضافة
   المحاولة كل 3 ثوانٍ.
3. افتح صفحة المزوّد (مثل `gemini.google.com`) وسجّل الدخول — يُسجَّل التبويب
   في الجسر تلقائياً.

التحميل المؤقت يسقط عند إغلاق المتصفح؛ الاستخدام الدائم يتطلب حزمة XPI موقّعة
(مع `xpinstall.signatures.required` في Firefox ESR). بعد إعادة التحميل تسقط
التسجيلات القديمة ويعيد الاتصال الجديد تسجيل نفسه.

**حسابات متعددة:** الحساب الثاني يعني فتح المزوّد في **حاوية Firefox ثانية**
(إضافة Multi-Account Containers). تبويب ثانٍ في الحاوية نفسها **ليس** حساباً
منفصلاً — الأحدث يحلّ محل تسجيل السابق؛ يلزم `cookieStoreId` مختلف. الاختيار
يكون على مستوى الحساب وفق الأقل استخداماً.

يتطلب الجسر الآن هوية:

- `Host` يجب أن يكون `127.0.0.1` أو `localhost` أو `[::1]` فقط (ضد DNS rebinding).
- يُقبل `Origin` إن غاب (عميل محلي) أو كان من مخطط إضافة
  (`chrome-extension://`، `moz-extension://`)؛ صفحات `http(s)://` تُرفض.
- الرمز المشترك إلزامي. يطبع كرڤان مساره عند التشغيل:
  `%LOCALAPPDATA%\kervan\eklenti.token` (في Linux/macOS
  `~/.local/state/kervan/eklenti.token`؛ وإن غاب `HOME` أيضاً،
  `kervan/eklenti.token` في دليل العمل). تجلب الإضافة الرمز من
  `GET /eklenti/token`، وهو مخصص لطلبات الإضافات فقط، وتخزّنه في
  `storage.local` — بلا أي عمل من المستخدم.

إصدار الإضافة القديم لا يستطيع الاتصال (لا يرسل رمزاً)؛ أعد تحميل `eklenti/`
وفق الخطوات أعلاه.

### مزوّدو REST المباشرون

المزوّد الذي يجب أن يصل إلى واجهته البرمجية دون تبويب متصفح يُعرَّف بـ
`[rest.<ad>]` (`bicim`: `openai`، `claude`، `gemini`). يُقرأ المفتاح من متغير
بيئة؛ لا يُكتب في الملف أبداً، ويظهر الهدف في `/v1/models` باسم `kervan/<ad>`.
التفاصيل وقواعد تعارض الأسماء في `kervan.toml.example`.

حدّ معروف: عند انقطاع العميل يتوقف مسار المتصفح عن الإنتاج، لكن نداء REST
الجاري لا يمكن إلغاؤه (عميل HTTP حاجب)؛ يستمر حتى `zaman_asimi` وتُهمل نتيجته.
الإصلاح الدائم عميل غير متزامن؛ مؤجّل عمداً.

### التوجيه

`model: "auto"` يسابق ثلاثة مصادر: تبويبات الإضافة المتصلة، مجموعة المتصفح،
وأهداف `[rest.*]`. تُختار الاستراتيجية عبر `[yonlendirme]`، وتُقرأ وتُغيَّر أثناء
التشغيل بـ `GET`/`POST /yonlendirme`. تُقبل 20 تسمية؛ 7 فقط تغيّر الترتيب فعلياً
في الإنتاج (`weighted`، `round-robin`، `p2c`، `random`، `strict-random`،
`least-used`، `lkgp`). من الـ13 الباقية: 8 لم تُنقل بعد (تحذير عند التشغيل)،
و5 بلا أثر صامت (`cost-optimized`، `context-optimized` — جداول السعر/السياق
فارغة؛ `priority`، `fill-first`، `context-relay` — النواة لا تمسّ الترتيب،
والمرشحون يأتون أبجدياً أصلاً). القائمة والمبررات: `kervan.toml.example`.
في الطلبات التي تحمل `tools` تُستبعد مرشحات المتصفح كلها متى وُجد مرشح REST.

| | |
|---|---|
| المتصفح | مبني على Firefox (Zen أو Firefox)، عبر geckodriver |

## ⚠️ المشاكل المعروفة / الميزات التجريبية

- **تعلم الحصة:** مزودو الويب لا يكشفون حالة الحصة. كرفان يسجل نتيجة كل طلب في `%LOCALAPPDATA%\kervan\kota.jsonl` ويحدد نفاد الحصة.
- **Cloudflare:** Claude و Deepseek و Qwen و Z.ai تواجه جدران Cloudflare في معظم الحسابات.
- **البوابة البشرية:** عند جدار التحقق، يوقف الحساب ويجلب النافذة إلى المقدمة — لا يوجد حل آلي.
